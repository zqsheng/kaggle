# Kaggriculture

一款农场模拟游戏，两名玩家通过向动态市场出售农产品来竞争收入最大化。

## 概述

每位玩家初始拥有一块空农场和少量启动资金。每回合，玩家可以执行移动、购买种子或牲畜、种植、浇水、收获农产品或动物产品，以及在市场上出售产品等操作。游戏运行固定时间（代表一个赛季），最终银行余额最多的玩家获胜。

对于作物，"每格每天产出"是总收获量除以该格占用天数（每天浇水并在产量峰值时收获）。对于动物，这是首次产出后的稳态生产速率（`1 / 间隔`）；只要持续喂食，动物会一直生产，因此没有固定的占用天数可除。动物的"最大产出"是`max_held`，即格子上*未收获*产品的上限，而非终生总产量。

作物"达到最大产出时间"是指在每天浇水的情况下产量停止增长的时间，这不一定是奖励窗口的结束：

- **甜瓜**的奖励窗口是第6-12天，但基础1加上每个浇水天增加1个单位，在第10天达到6个的上限，所以第11-12天没有增加。施肥在第8天达到上限。
- **小麦**和**胡萝卜**只有在施肥时才能达到列出的最大产出6和4；仅浇水最高只能达到4和3。
- **番茄**和**草莓**是持续性但*非*无限期的：生产上限为4次计划产出（番茄在第8-11天，草莓在第10、12、14、16天），之后植物会腐烂变成杂草。

所有植物必须每天浇水。连续两天不浇水会变成杂草。所有动物必须每天用小麦喂食。连续两天不喂食会逃跑且无法找回。小麦也可以在市场上按当前价格购买。

## 操作

每回合玩家可以执行一个操作。每天24回合，赛季30天——共720回合。

### 农民/农工操作

每个农民/农工每回合可以执行一个操作。农民和农工可以站在同一格。

#### 移动

- NORTH、SOUTH、EAST、WEST——向该方向移动一格。移出棋盘边缘无效果。锁定的格子可通行：单位可以移动到未购买的区域，但在锁定格子上执行种植、浇水、建造等操作无效且不消耗任何物品。

#### 谷仓

从谷仓拾取物品（必须正交相邻）放入库存

- PICKUP `<物品>` `[n]`——将最多`n`个`<物品>`（默认1）从谷仓移入当前农民/农工的库存。谷仓中的任何物品都有效（动物、肥料、收获的农产品等）。种子存放在单独的槽位，永远不会被拾取——PLANT直接消耗它们。
- DROP——正交相邻于谷仓时，将当前农民/农工的全部库存倒入谷仓。超过`shedCapacity`的物品会被丢弃。不在谷仓相邻位置时无效。

#### 植物

- PLANT——种植从市场购买的种子
  - 种子自动对所有农民/农工可用
  - 如果在特定回合尝试种植过多，全部种植失败
    - 例如：你有1个甜瓜种子，但两个单位同时执行PLANT MELON命令
- WATER——给植物浇水。每天只需浇水一次，同一天后续浇水无效。
- HARVEST——收获植物的农产品。如果植物没有后续产出，将从地图上移除。每次收获操作至少产出一个单位的作物，根据浇水和施肥情况可能有额外产量（公式因作物类型而异——见下方收获产量）。收获的物品添加到库存中。
- FERTILIZE——给植物施肥以增加潜在产量（见下方收获产量）。
  - 在接下来3天内将每日产出奖励翻倍。奖励仅在植物当天也浇水时生效（基本需求优先）。

#### 动物

- PLACE `<物品>` `[n]`——将物品从当前农民/农工库存放入格子或谷仓：
  - **放置动物**：站在匹配的空闲结构上（鹅放鸡舍，羊/牛放牧场）将库存中的一个动物放到格子上。`n`参数被忽略。
  - **放入谷仓**：正交相邻于谷仓时，将最多`n`个（默认1）`<物品>`从库存移入谷仓。受`shedCapacity`限制；多余物品留在库存中。
- FEED——用小麦喂食动物（每天只需一次）
- HARVEST——收集动物产出的鸡蛋/牛奶/羊毛。
- COLLECT_FERTILIZER——从动物收集1个肥料。每个存活的动物每天结束时产生1个肥料，无论是否喂食或照料。未收集的肥料不会累积，所以五天未照料的动物仍然只产出1个单位。
- CARE——照料动物（每天一次，已照料则无效）。见下方动物照料。

#### 动物照料

CARE存储一个产出奖励，在动物下次计划生产时兑现：

* 每天结束时，如果动物当天既喂食又照料，`pending_care_bonus`增加1。动物未喂食的天数不存储奖励（基本需求优先）。
* 在计划生产日，如果动物已喂食，整个存储的奖励将加到该次生产的产量中（在基础1之外），存储清零。
* 如果动物在生产日未喂食，仍产出基础1个单位，但存储的奖励不兑现，存储清零。
* `pending_care_bonus`受每个动物的`yield_units`上限`max_held`间接限制。

#### 地形

- BUILD_COOP——在空闲格子上添加鸡舍
- BUILD_PASTURE——在空闲格子上添加牧场
- DIG——移除格子上的植物以腾出空间，或移除杂草（不产出任何农产品），或移除**空的**鸡舍/牧场。有动物的鸡舍或牧场无法挖掘；DIG无效。

#### 其他

- PASS——无事可做时的默认操作（可选）

### 市场操作

每回合最多提交`maxMarketOrdersPerTurn`（默认10）个市场操作；超出限制的订单会被静默丢弃。这是一个有序列表，市场订单将按顺序同时处理（每位玩家一个），当两位玩家都有订单时。

- BUY_SEED——从市场购买N个单位的单个物品。
  - BUY_SEED WHEAT 1
- BUY_ANIMAL——
  - BUY_ANIMAL GOOSE 1
- BUY_PRODUCT——
  - BUY_PRODUCT WHEAT 1
  - BUY_PRODUCT FERTILIZER 1
- SELL——向市场出售N个单位的单个物品。
  - SELL WHEAT 1
- HIRE——雇佣一名农工。同一天雇佣额外农工成本递增。
- BUY_LAND——解锁新的5×5区域用于种植。成本递增。
  - 费用为：$1k、$2k、$4k

## 浇水/动物饲料

植物（和动物）必须至少每隔一天浇水/喂食。每天只需浇水一次，后续浇水操作无效。植物连续两天不浇水，当天结束时会变成杂草。动物连续两天不喂食会逃跑（无法找回）。

新种子以`consecutive_unwatered = 1`开始——种植日本身算作第一个未浇水日。当天种植且未浇水的种子在当天结束刷新时达到2，当晚变成杂草，在生长之前。新种植没有宽限期。

新放置的动物以`consecutive_unfed = 0`开始，所以它在第一天未喂食时能存活。

请注意，在产出窗口期间浇水一次性产出植物会导致更高产量。这对持续性产出的植物/动物不适用。见下方。

## 收获产量

植物可能根据照料情况有更高产量。

* **一次性作物**（小麦、胡萝卜、甜瓜）：从植物`max_yield_day`（达到最大产出时间）的一半开始（向上取整），在奖励窗口期间浇水每天增加一个单位的总可收获产量。
  * 施肥的植物每天增加2个单位。
* **持续性作物**（番茄、草莓）：计划生产以固定间隔进行。基础产量为每次计划产出1个。如果植物当天既施肥又浇水，产量翻倍为2。
* 一旦植物达到最大寿命，植物上可用的总产量每回合减少1个单位，直到为0，此时植物变成杂草。
  * **一次性作物**在`max_yield_day`后一天达到最大寿命。
  * **持续性作物**在累计生产次数达到`max_yield`后一天开始腐烂（即它们已触发足够次数的计划生产达到上限，无论产品是否已收获）。

## 地图特征

每位玩家拥有自己的农场，包含固定数量的格子。玩家无法看到对手谷仓的状态，但可以看到对手农场的状态。

### 农场空间

- 农场附近的土地是`boardSize` × `boardSize`的网格（默认10×10），分为四个5×5的区域。最初，你的农场覆盖一个区域（25%的格子）。通过支付递增的费用，你可以购买相邻区域，最终覆盖100%的格子。
- 每个植物或动物占用农场上的一个格子。
- 玩家可以自由分配这些格子用于作物和牲畜。没有按类型的特定限制。
- 杂草有机会在农场任何空格子上生长，必须清除后才能用于其他用途。
- 农场上的格子可以是植物、鸡舍/牧场、杂草或空地。

### 谷仓（库存）

- 作为已收获但未出售物品，或未种植种子的库存
- 农民和雇佣的农工每天开始时在谷仓生成
- 农民和雇佣的农工每天结束时将库存放入谷仓（如果有空间）
- 限制为100个物品（不含种子）。谷仓满后，任何额外添加的物品（通过中途PLACE或结束时库存投放）都会被丢弃——没有溢出存放区，所以在农民/农工库存中囤积不会绕过上限。

谷仓位于棋盘中心，不是一个格子——它永远不会出现在`tiles`数组中，该数组的值只有`None`、`"LOCKED"`和结构字典。"正交相邻于谷仓"意味着站在四个中心格子之一，`(half-1, half-1)`、`(half, half-1)`、`(half-1, half)`、`(half, half)`，其中`half = boardSize // 2`。默认`boardSize = 10`时，这些是`(4,4)`、`(5,4)`、`(4,5)`和`(5,5)`，每个区域一个。

### 农民/农工

#### 雇佣

- 雇佣是市场操作（`HIRE`）。每天雇佣额外农工的成本递增。每天结束时，所有农工将库存放入农场并消失（需要每天重新雇佣）
- 成本为`farmHandCostMult * fib(n)`，其中`n`是当天已雇佣次数（斐波那契从1, 1, 2, 3, 5, 8, 13, ...开始）。
  - 默认`farmHandCostMult = 1`时：1, 1, 2, 3, 5, 8, 13, 21等...（每天开始时重置）
- 雇佣的农工在谷仓正交相邻的空闲位置生成，按西北东南顺序。如果没有空位，选择占用最少的格子，按西北东南顺序打破平局。
- 生成位置忽略格子是否锁定。由于主农民从`(4,4)`开始，最少占用规则将每天第一个雇佣送到`(5,4)`，该位置在购买东北区域前是锁定的。锁定格子可通行，所以生成在上面的农工可以移回未锁定区域。

#### 库存

- 收获或拾取物品时，它们被添加到库存。
- 可以将物品放入谷仓
- 每天结束时，所有库存中的物品将添加到谷仓库存（如果有空间）。任何放不下的物品都会被丢弃——溢出部分丢失。

### 城镇建筑

随着赛季进展，新商店以固定间隔解锁（每`townShopUnlockInterval`天，默认3）。每次解锁从尚未添加的商店中随机选择；一旦解锁，商店在游戏剩余时间内保持活跃。随着更多商店解锁，总需求单调增长。

每个解锁的商店每`townShopSellInterval`回合（默认4）消耗它所需的所有产品各一个单位。所以默认间隔下，需要小麦的商店每天从市场移除6个小麦。单产品商店消耗2倍。

此外，城镇中心每`townCenterSellInterval`回合（默认12）消耗所有产品（不含肥料）各一个单位。第10天后增加到各2个，第20天后增加到各4个。

| 商店类型 | 增加对以下物品的需求 |
| :---- | :---- |
| 面包店 | 鸡蛋、小麦 |
| 披萨店 | 牛奶、番茄、小麦 |
| 早午餐点 | 鸡蛋、小麦、草莓 |
| 毛线店 | 羊毛（2倍） |
| 冰淇淋店 | 草莓、牛奶、小麦 |
| 宠物咖啡馆 | 胡萝卜（2倍） |

| 农贸市场 | 小麦、胡萝卜、番茄、草莓 |

## 市场机制

市场以固定价格无限供应种子和动物。然而，销售价格根据资源动态变化，并跨天持续。

每个产品（和肥料）游戏开始时市场库存为`I0 = 10,000`单位，远超任何单局游戏的实际产量，因此库存基本保证保持正数。产品的销售价格在`I0`时为`base`，随着库存下降（玩家购买或城镇消费消耗供应）而上升，随着库存增长（玩家出售）而下降。

### 向市场出售库存

玩家可以在市场操作列表中排队任意数量的出售或购买订单（任意数量）。订单在玩家间并发处理，一次一个单位。例如，当两位玩家都先发出`SELL CARROT 10`时，我们取当前胡萝卜价格，给两位玩家第一个胡萝卜的价格，然后向市场添加2个胡萝卜（每位玩家1个）——这可能会改变价格——重复直到两个订单完成。

如果销售价格降至$1（价格下限），单位仍被购买但*不*添加到市场库存，因此下限对后续购买保持响应。

### 从市场购买库存

只有`WHEAT`和`FERTILIZER`可以通过`BUY_PRODUCT`从市场购买（其他产品在市场上出售但不回购）。出售不受限制：每个产品，包括从动物收集的肥料，都可以通过`SELL`出售。两件事消耗市场库存：城镇建筑（城镇中心和商店，免费消耗产品）和玩家`BUY_PRODUCT`订单。购买订单遵循与出售订单相同的一次一个单位的并发流程。如果玩家在订单中途资金用尽，订单停止。

购买价格按购买后库存报价，出售价格按出售前库存报价，因此立即购买然后出售同一物品，在其他条件不变的市场中净收益正好为零。

### 价格函数

对于每种资源，曲线由基础价格、锚定吞吐量`T`，以及平衡两侧独立的**形状函数**和**目标移动**定义：

```
price(inv) = base + sign · amp · f(|inv − I0|)
  sign = +1  if inv < I0   （稀缺 → 价格上涨）
  sign = −1  if inv > I0   （过剩 → 价格下跌）
  amp  = target · base / f(T)        （派生；不存储）
  f    ∈ { linear, sq, sqrt, log, log10 }   （log使用ln(1+x)，所以f(0)=0）
```

下限为$1，四舍五入到最近的美元。

`T`是单个5×5田地在24天窗口内以最优浇水（无肥料）的生产能力（动物总量已预先打折30%以考虑小麦饲料开销，并允许一天建造鸡舍或牧场）。24天窗口是校准范围，不是30天赛季长度。它刻意更短：开局几天设置密集，产量很少。

`target`表示"超过`I0`移动`T`个单位使价格移动`target × base`"。在每侧选择不同的`f`和`target`可以让具有相似生产特征的资源在策略上表现非常不同——小麦在稀缺时恐慌但在过剩时吸收，胡萝卜相反；甜瓜对稀缺几乎不反应但在生产过剩时崩溃；羊毛在较小规模上类似甜瓜。高端资源（基础价格 > $100：草莓、甜瓜、牛奶、羊毛）使用`above_target > 1`，所以即使是适度的过剩也会直接将它们推向$1下限——对于这些资源，捆绑和把握销售时机比主食更重要。

| **羊毛** | 200 | 10,000 | 105 | log | 0.20 | sq | 3.20 | $240 | $1 | $1 |
| **肥料** | 100 | 10,000 | 200 | linear | 0.40 | linear | 0.40 | $140 | $60 | $20 |

默认值位于`kaggriculture.py`中的`MARKET_PARAMS`。每个资源的覆盖（稀疏：`base`、`I0`、`T`、`below_func`、`below_target`、`above_func`、`above_target`的任意子集）可以在创建episode时通过`env.configuration["marketParams"]`提供，无需修改代码，例如`{"WOOL": {"above_target": 0.95}}`。

## 回合处理顺序

1. **操作验证**——验证操作合法性
2. **玩家操作**——记录每位玩家执行的操作（同时发生）
3. **市场操作**——按玩家顺序处理市场队列（如上所述）
4. **城镇购买操作**——城镇中心和商店减少库存
5. **更新观察**
   - **日刷新**——如果适用，更新植物和动物的新一天状态，将喂食/浇水状态重置为false
   - **市场刷新**——根据上回合的销售修改市场上物品的价格
   - **收入更新**——根据任何购买或出售更新玩家银行
   - **农场更新**——清除已收获的植物、已使用或出售的库存物品、向农场添加新的植物/动物等

## 胜利条件

胜利条件很简单——赛季结束时银行余额最多的玩家获胜。两位玩家也可能平局。

## 奖励

游戏结束时银行余额最多的玩家获胜。库存中未出售的物品不计入总数。

## 观察格式

传递给每个agent的顶级观察：

```py
{
  "player": int,           # 0或1
  "day":    int,           # 从0开始的游戏天数
  "hour":   int,           # 当天内的回合索引（从0开始）
  "farms":  [farm, farm],  # 公开的每位玩家状态，按玩家id索引（共享）
  "market": {              # 共享
    "inventory": { "WHEAT": int, "CARROT": int, ... },
    "prices":    { "WHEAT": int, "CARROT": int, ... },
  },
  "town": {                # 共享
    "unlocked_shops": ["BAKERY", ...],
  },
  "private": {             # 仅限本玩家；对手的私有状态不可见
    "shed":        { "WHEAT": int, "GOOSE": int, "FERTILIZER": int, ... },
    "seeds":       { "WHEAT": int, "CARROT": int, ... },
    "inventories": [farmer_inv, hand_inv, ...],  # [0]是主农民
  },
}
```

每个`farm`字典（公开，双方玩家可见）：

```py
{
  "money":              float,
  "tiles":              [[tile, ...], ...],   # tiles[y][x]
  "farmer":             [x, y],
  "hands":              [[x, y], ...],         # 当天雇佣的农工
  "unlocked_quadrants": ["NW", ...],          # {"NW","NE","SW","SE"}的子集
  "hires_today":        int,                  # 用于确定下次HIRE的成本
}
```

`tile`是以下之一：

- `None`——空的已解锁格子
- `"LOCKED"`——玩家尚未购买的区域中的格子
- 植物字典：
  ```py
  {
    "kind":                 "PLANT",
    "crop":                 "WHEAT" | "CARROT" | "TOMATO" | "STRAWBERRY" | "MELON",
    "planted_day":          int,
    "watered_today":        bool,   # 每天结束时重置为False
    "consecutive_unwatered": int,   # 2+ → 格子变成杂草
    "yield_units":          int,    # 当前可收获的单位数
    "max_lifespan_step":    int,    # 开始腐烂的回合；持续性作物为-1
    "fertilized_until_day": int,    # 肥料奖励适用的最后一天；无则为-1
  }
  ```
- 杂草字典：`{"kind": "WEED"}`
- 动物结构字典（鸡舍/牧场，可选占用）：
  ```py
  {
    "kind":                 "COOP" | "PASTURE",
    "animal":               "GOOSE" | "COW" | "SHEEP" | None,  # PLACE前为None
    "placed_day":           int,
    "yield_units":          int,
    "fed_today":            bool,
    "consecutive_unfed":    int,    # 2+ → 动物逃跑
    "cared_today":          bool,
    "fertilizer_available": bool,   # 每个存活动物每天结束时设置；COLLECT_FERTILIZER清除
    "pending_care_bonus":   int,    # 存储的CARE奖励，在下次产出时兑现
  }
  ```

## 快速开始

```py
from kaggle_environments import make


def my_agent(obs):
    # 第一回合购买一个小麦种子，之后永远PASS。
    if obs.get("step", 0) == 0:
        return {"farmer": ["PASS"], "market": [["BUY_SEED", "WHEAT", 1]]}
    return {"farmer": ["PASS"], "market": []}


env = make("kaggriculture", configuration={"episodeSteps": 200})
env.run([my_agent, "random"])
env.render(mode="ipython", width=800, height=800)
```

## 配置默认值

每种作物的种子成本和每个产品的基础价格不可配置；它们在上面的物品类型和价格函数表中记录。可配置的参数有：

| 参数 | 默认值 | 描述 |
| :---- | :---- | :---- |
| episodeSteps | 720 | 赛季总回合数（24回合 × 30天） |
| boardSize | 10 | 每位玩家方形农场的宽度和高度（格子数）。高级用法10 = 四个5×5区域 |
| startingMoney | 3000 | 每位玩家初始金币 |
| maxMarketOrdersPerTurn | 10 | 每回合每位玩家处理的最大市场订单数；额外订单被静默丢弃 |
| turnsPerDay | 24 | 构成一个游戏天的回合数 |
| shedCapacity | 100 | 谷仓可容纳的最大非种子物品数；结束时投放溢出部分被丢弃 |
| weedSpawnChance | 0.005 | 每个空已解锁格子在每天结束刷新时生成杂草的概率 |
| townShopUnlockInterval | 3 | 相继城镇商店解锁之间的天数 |
| townShopSellInterval | 4 | 每个解锁城镇商店消耗之间的回合数 |
| townCenterSellInterval | 12 | 城镇中心消耗之间的回合数 |
| seed | null | 可选的输入种子，用于确定性episode生成；读取后从配置中清除，使其不出现在agent观察中 |
